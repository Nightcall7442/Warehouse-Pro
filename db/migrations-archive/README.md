# Архив миграций 0000–0050 (до 1 сентября 2026)

Эти файлы **не читаются мигратором**. Он смотрит только в `db/migrations`.
Лежат здесь как история изменений схемы — их можно читать, но запускать
нечем и незачем.

## Почему их убрали

Цепочку из 51 файла нельзя было накатить на пустую базу. Работа
`test-migrations` в CI поднимает чистую MySQL 8 и катит всю историю с 0000 —
и не проходила **ни разу**. Причин было две, и обе неисправимы косметически:

**Файлы писали по живой базе, а не по собственной истории.** Миграция 0009
строит индекс по `warehouse_stock.warehouse_id`, хотя эта колонка появляется
только в 0012. Она же удаляет внешние ключи с автоименами MySQL
(`shops_ibfk_1`, `orders_ibfk_2`, …), которых в 0000 нет — там имена явные.
И ссылается на таблицу `stock_transfers`, которую создаёт 0012. Всё это
сходится только на той базе, что собиралась `drizzle-kit push` постепенно.
Проверено на пустой базе: цепочка умирает на 0009 с
`Key column 'warehouse_id' doesn't exist in table`.

**Синтаксис MariaDB.** Восемнадцать операторов в десяти файлах написаны как
`ADD COLUMN IF NOT EXISTS` и `DROP INDEX IF EXISTS` — этих форм в MySQL 8
нет, он отвергает их как синтаксическую ошибку. На боевой базе это было
незаметно: миграции туда доезжали не все, недостающее досыпали руками.

## Чем заменили

Одним файлом `db/migrations/0000_baseline.sql`, собранным `drizzle-kit
generate` прямо из `db/schema.ts`. Он создаёт всю схему за один прогон.

Метка времени у него — `1782062632383`, ровно та, что была у прежней
`0000_baseline`. Это и есть весь механизм:

* На **боевой** базе такая запись в `__drizzle_migrations` уже есть, и
  последняя применённая там новее. Мигратор применяет только то, что новее
  последней применённой (`mysql-core/dialect.js`), поэтому baseline
  пропускается. Содержимое файлов нигде не сверяется — `hash` пишется, но не
  проверяется, — так что подмена файлов боевую базу не задевает вовсе.
* На **чистой** базе записей нет, и baseline строит схему целиком.

Проверено 1 сентября 2026 на отдельной пробной базе: схема, собранная с нуля,
совпала с боевой по всем 48 таблицам и по всем колонкам, кроме
`stock_transfers.updated_at` — эта колонка есть на бою, но её нет ни в
`db/schema.ts`, ни в коде; давний нарост, к сворачиванию отношения не имеет.

## Если понадобится посмотреть, как менялась схема

`git log --follow db/migrations-archive/<файл>` — вся история правок на месте.
