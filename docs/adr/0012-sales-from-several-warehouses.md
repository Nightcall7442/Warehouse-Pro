# 0012. Продажи с нескольких складов — по выбору организации

Дата: 2026-10-21. Решение владельца. Отменяет ADR 0008 только для
организаций, которые отметили точки продаж; остальные живут по 0008.

## Контекст

21.10.2026 владелец попросил перенять сильные стороны конкурента. Одна из
них — продажа с нескольких складов: у дистрибьютора с филиалом агенты филиала
продают с полки филиала. По ADR 0008 они продавали товар основного склада,
который лежит за сотни километров, а остаток своего склада видели только в
отчётах.

Доводы 0008 остаются верными: сумма остатков по складам обещает товар,
которого на отгрузке нет, а заказ отгружают с одного склада. Поэтому решение
не «продавать отовсюду», а «у каждого заказа свой склад».

## Решение

По умолчанию ничего не меняется. Пока директор не отметил ни одного склада,
организация продаёт только с основного, как в 0008.

Директор отмечает склад **точкой продаж** («Настройки → Склады»,
`warehouses.is_sales_point`) и закрепляет за ним сотрудников
(«Пользователи», `users.warehouse_id`). Склад заказа выбирается одним
правилом (`api/services/sales-warehouse.ts`):

1. **Выбранный офисом.** Склад выбирают только директор и оператор, и только
   действующий основной склад или точку продаж своей организации. Полевым
   ролям выбор запрещён: им склад назначает директор. Отказ приходит как
   BAD_REQUEST, потому что офлайн-очередь телефона повторяет FORBIDDEN без
   конца.
2. **Склад агента заказа**, пока с него продают. Если отметку сняли или склад
   отключили, агент возвращается к основному.
3. **Основной склад.**

Заказ запоминает свой склад (`orders.warehouse_id`). Правка, отгрузка,
отмена, возврат и погрузочный лист идут по складу заказа, а не по правилу.
Старым заказам без склада остаётся только основной, без склада агента: их
резерв лёг на основной, и снимать его с другого склада нельзя.

Каталог (`product.listAll`, `list`, `getById`, поиск по штрихкоду) читает
остаток по тому же правилу, поэтому агент видит остаток склада, с которого
спишется его заказ.

- Склад входит в оба ключа кэша каталога.
- `orderId` даёт склад правимого заказа.
- `agentId` даёт склад агента, на которого оформляют заказ: так работают
  директор, оператор и супервайзер.

Сумма по складам по-прежнему нигде не показывается.

Уценка партии действует только на заказы склада этой партии. Ставят её
только на партию склада, с которого продают. Правило «одна уценка на товар»
сохраняется: уценка на основном складе не дешевит товар на складе филиала.

## Последствия

**Идёт по складу заказа или по складам продаж:**

- Погрузочный лист собирают с одного склада. Если в листе заказы разных
  складов, сервер отказывает и перечисляет склады с номерами заказов.
- Возврат по заказу ложится на склад заказа. Возврат без заказа идёт на
  основной склад.
- Публичный API фильтрует `warehouse_id` по складу заказа (старые заказы
  считаются заказами основного склада) и отдаёт склад в каждой строке.
- Тревога крона «заканчивается» срабатывает на основном складе и на
  действующих точках продаж. Не основной склад назван в тексте, в том числе
  в сообщении Telegram. Склад хранения тревогу не шлёт: там нехватка — повод
  для перемещения.
- Сроки годности. «Лежит не там» теперь значит «лежит на складе, с которого
  не продают». Темп продаж партии считается по товару, а не по складу. Это
  приближение: при равных сроках партии двух складов делят один темп.

**Остаётся на основном складе:**

- Экраны «что заканчивается», `reorderAlerts` (мобилка читает его той же
  формы), ответы бота в Telegram, сводка дня и ABC-анализ. Их ответ — список
  товаров без склада, и строка на каждый склад задвоила бы товар.
- Обмен с 1С: остатки и документы идут по основному складу. Сопоставление
  складов 1С со складами здесь — отдельное решение.
- Приход, ручная корректировка, возврат поставщику и импорт без явного
  склада идут на основной.

**Охрана:**

- Склад, с которого продают, нельзя отключить или снять с него отметку,
  пока за ним закреплены сотрудники. Склад, на котором лежит резерв открытых
  заказов, тоже нельзя отключить. Основной склад не отключают совсем. Каждый
  отказ объясняет, что сделать сначала.
- Отметка склада и назначение сотрудника пишутся в журнал действий
  (`warehouse.updated`, `user.updated`).
- `users.warehouse_id` нарочно без внешнего ключа: при уходе организации
  пользователи удаляются последними (ADR 0006). Принадлежность склада
  организации проверяет `user.update`.
- Сменить основной склад по-прежнему можно только без открытых заказов и
  резерва.

**Мобилка.** Сервер уже принимает `orderId` в `product.listAll`. Экран правки
заказа в мобилке должен передавать его, чтобы видеть остаток склада заказа.
Это следующий шаг мобилки. Пока он не сделан, правка заказа филиала в
телефоне показывает остаток склада агента, а сервер всё равно проверяет
склад заказа.
