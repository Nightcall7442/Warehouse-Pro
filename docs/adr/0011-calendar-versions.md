# 0011. Календарные версии, CHANGELOG из тем коммитов

Дата: 2026-09-12. Код: `scripts/release.mjs`, `.github/workflows/release.yml`, `CHANGELOG.md`.

## Контекст

968 коммитов без единой метки; версия в `package.json` — «1.0.0» с первого дня.
«Что вошло в эту выкладку» отвечали по памяти; Sentry различал выкладки только
по хешу коммита.

## Решение

Версия календарная: `v2026.09.13[.N]`. `node scripts/release.mjs 2026.09.13`
собирает раздел CHANGELOG из тем коммитов с прошлой метки, пишет версию,
коммитит и ставит метку; push метки публикует Release на GitHub. Семантические
версии тут ничего не значили бы: одна ветка, выкладка каждый день, внешнего
API с обещаниями совместимости нет (публичный REST версионирован путём `/api/v1`).

## Последствия

Тема коммита — предложение о том, что изменилось для дела: она попадает в
CHANGELOG как есть. История до 11.09.2026 остаётся без меток — разделять её
задним числом незачем.
