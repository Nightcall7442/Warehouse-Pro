# 0002. Миграция — только DDL или одно идемпотентное выражение

Дата: 2026-09-12. Код: `db/migrations/README.md`, `api/lib/migration-catchup.ts`,
страж `migration-one-ddl-or-idempotent`.

## Контекст

Мигратор drizzle сравнивает одну метку времени: запись «из будущего» глушит
всё после неё молча — так бой ронялся дважды. Файл, упавший на середине,
оставлял базу наполовину применённой, и повторный запуск падал на «already
exists». Миграции с данными (UPDATE по всей таблице) при повторе портили то,
что уже было исправлено.

## Решение

С 0028: файл миграции — либо только DDL (CREATE / ALTER / индексы), либо ровно
одно идемпотентное DML-выражение (`INSERT … ON DUPLICATE KEY`, `UPDATE … WHERE`
с условием, которое второй раз ничего не найдёт). Загрузчик на «already
exists» не падает — догон доводит наполовину применённый файл. Каждая миграция
генерируется `drizzle-kit generate` вместе со снимком; написанная руками без
снимка роняет CI.

## Последствия

Перенос данных, требующий нескольких шагов, — отдельный скрипт или крон, а не
миграция. Правило проверяется тестом на каждый файл с 0028.
