# 0006. Уход организации: три замка, детьми вперёд, одной транзакцией

Дата: 2026-09-12. Код: `api/services/tenant-offboard.ts`, страж `tenant-offboard`.

## Контекст

Данные ушедшего клиента (заказы, сотрудники, GPS-следы) жили в базе навсегда:
ручки не было. Закон о персональных данных требует удалить их по исчерпании
цели; бывший клиент вправе потребовать. При этом в продукте действует правило
«массовой очистки нет» (страж `no-mass-wipe`): у оператора нет случая стирать
историю продаж.

## Решение

Уход — действие платформы, не арендатора, и оно закрыто тремя замками: только
суперадмин, только приостановленная организация (решение уже принималось
однажды), slug набран руками и код второго фактора (ADR 0005). Внешние ключи
остаются `restrict` — они ловят ошибки в рабочих путях, — поэтому 57 таблиц
стираются детьми вперёд в одной транзакции; таблицы без `tenant_id` — через
родителя (`DELETE … JOIN`). Порядок — список в коде, проверяемый стражем по
`db/schema.ts`: новая таблица с `tenant_id`, забытая в списке, роняет тест.

Резервные копии хранят данные до истечения своего срока — это «разумный срок»
по закону, отдельно копии не чистятся.

## Последствия

Каждая новая таблица арендатора попадает в список ухода сразу (тест). Уход
необратим по замыслу; экран показывает, что будет стёрто, до подтверждения.
