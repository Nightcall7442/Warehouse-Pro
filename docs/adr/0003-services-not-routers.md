# 0003. Правила дела живут в службах; службы не импортируют роутеры

Дата: 2026-09-12. Код: `api/services/*`, страж `services-do-not-import-routers`.

## Контекст

Аудит 11.09.2026: 27 транзакций в роутерах против 18 в службах; доставка
курьера (700 строк) и проведение прихода лежали внутри tRPC-процедур, и крон,
вебхук 1С и публичный API не могли их вызвать — их начали бы копировать (долг
агента и долг магазина уже разошлись именно так). Службы при этом тянули
`telegram-router` ради одной функции отправки — правило зависело от транспорта.

## Решение

Роутер — транспорт: zod, права, контекст. Правило дела — функция службы с
подписью `(db, tenantId, [userId], input)` и явным типом входа; `ctx` внутрь не
заходит. Транспорт Telegram — в `lib/telegram.ts`. Страж запрещает файлам в
`services / cron / lib / http / webhooks / telegram` импортировать `*-router`
(исключение — мост tRPC, которому нужен корневой роутер).

Крупные файлы разрезаны без изменения поведения: `services/order.ts` — фасад над
шестью модулями, `boot.ts` — плюс `http/auth`, `http/backup`, `http/trpc-adapter`.

## Последствия

Стражи, читающие исходники как текст, идут через `__tests__/helpers/*-source.ts`.
Zod в службах не живёт: типы входа пишутся руками и проверяются компилятором
против zod-схемы роутера.
